ACC/Nomad — Documento Técnico de Handoff
Guia de onboarding para novo mantenedor. Última atualização: 2026-08-21. Objetivo: entender o projeto, o que já funciona, o que falta, e como operar — sem depender de conhecimento prévio.
1. O que é o projeto
Cliente: Osvaldo e Nahim — ACC (Automação de Controle Contábil).
Sigla interna: PRJ-020 · Produto: Nomad ·
Status: ~90% concluído (operação assistida).
Objetivo de negócio: analisar extratos bancários em PDF (diferentes bancos, formatos e estruturas visuais), extrair as movimentações, classificar por plano de contas e entregar relatórios gerenciais (PMG), substituindo planilhas manuais.
Classificação dos lançamentos: por plano de contas adaptado por segmento (comércio, saúde, agro, serviços), com revisão humana obrigatória no início (feedback loop).
Público-alvo: empresas do Simples Nacional, pequenos comércios, clínicas e autônomos.
Escala alvo: ~400 documentos/mês para ~100 clientes.
2. Arquitetura geral
2.1 Workflow n8n (núcleo do sistema)
Detecção de banco via GPT-4o-mini (OpenAI) com prompt estrutural.
Regras de negócio: ACC-001 (detecção de banco por prompt) · ACC-002 (tesouraria).
3. Fluxo de processamento (pipeline)
Upload — o usuário envia 1+ PDFs de extrato no dashboard Lovable (Nomad).
Webhook — o Lovable dispara o workflow no n8n.
Identificação do banco — n8n (Switch Node) + OpenAI (GPT-4o-mini) identificam o banco emissor e roteiam o caminho correto.
Análise visual (PDFlib) — extrai coordenadas, cores e colunas para distinguir crédito/débito (varia por banco).
Chunking — extratos grandes são divididos em chunks, sempre acompanhados da primeira página (contexto).
Extração e classificação (Claude) — extrai lançamentos e classifica por plano de contas (instrução personalizada opcional).
Organização — nó Code reorganiza em ordem cronológica (ex.: Itaú vem em ordem decrescente).
Persistência — dados salvos no Supabase (via Lovable).
Entrega — relatório PMG gerado; exportação “Fluxo de Caixa Aprovado” replica no modelo de planilha do cliente.
Revisão humana — classificação validada (essencial no início; alimenta o feedback loop).
4. O que funciona hoje (implementado)
Ingestão de extrato PDF multi-banco, com switch por banco.
Identificação automática do banco emissor (OpenAI GPT-4o-mini, prompt estrutural).
Análise visual (PDFlib) para crédito/débito em formatos variados (sinal, letra C/D, cor, colunas).
Extração e classificação de lançamentos (Claude) por plano de contas.
Divisão em chunks (+ primeira página) para extratos grandes.
Ordenação cronológica por banco (reorganiza a ordem decrescente do Itaú).
Persistência no Supabase via Lovable (deleção espelhada quando o cliente deleta).
Relatório PMG (Painel de Metas Gerenciais).
Exportação “Fluxo de Caixa Aprovado” no modelo do cliente.
Report de erro (Ticketed Support) em planilha.
Login de usuários com senha criptografada + recuperação de senha.

10. Como operar (roteiro rápido)
Antes de mexer em sistema externo: ler a documentação da integração e confirmar o ambiente (EasyPanel = produção).
Após reinício/rebuild do servidor: verificar se a PDFlib ainda está instalada; se removida, reinstalar via tutorial do handoff.
Testar ingestão: enviar um extrato pelo dashboard Lovable e acompanhar a execução no n8n.
Deploy/edição de workflow: sempre backup (exportar JSON) antes → editar → salvar → reler o workflow para confirmar o estado real.
Debug: abrir a execução com falha e ler o output de cada nó (não só o último); o erro costuma estar no nó HTTP do Claude — copiar o JSON de entrada e o de saída e comparar.
Monitorar o saldo de créditos de análise (não deixar zerar) e os custos na planilha.
Confirmação: toda mudança em produção exige prova do efeito esperado (reler o estado real, não confiar na memória).
